# Markdown 가이드

Naru는 `content/posts/`와 `content/pages/` 아래의 UTF-8 Markdown 파일을 읽습니다.
파일은 YAML front matter로 시작해야 하며 `---` 한 줄로 본문과 구분합니다.
게시물의 `category`를 생략하면 `content/posts/` 아래 첫 번째 폴더명을 사용합니다.
명시한 `category`는 폴더명보다 우선하며 일반 페이지에는 이 규칙을 적용하지 않습니다.
기존 사이트에서 하위 폴더를 정리 용도로만 사용했다면 폴더명이 카테고리로 반영될 수
있으므로 원하는 `category`를 명시하고 빌드 결과를 확인하세요.

## Front Matter

```markdown
---
title: Markdown 문법 예제
nav_title: 문법 예제
slug: markdown-example
description: Naru에서 지원하는 Markdown 문법 예제입니다.
published_date: 2026-11-17
updated_date: 2026-11-17
category: blog
tags:
  - markdown
---

# 본문
```

`title`, `nav_title`, `slug`, `description`, `published_date`,
`updated_date`, `tags`는 필수입니다. 날짜는 `YYYY-MM-DD`, 슬러그는 영문 소문자와
한글, 숫자 및 하이픈으로 작성합니다. 슬러그·카테고리·태그는 NFC로 정규화하며
URL의 한글은 퍼센트 인코딩합니다. 잘못된 YAML은 원본 파일과 줄 번호를 포함한 오류로
빌드를 중단합니다.

한글 카테고리가 이전에 `notes` 등으로 생성됐다면 주소가 달라질 수 있습니다.
기존 링크를 유지하려면 사이트의 `naru.yml`에 이전 주소를 새 주소로 연결하세요.

```yaml
category_redirects:
  notes: 개발
```

## 게시 제어

`draft: true`인 문서와 `published_date`가 현재 UTC 날짜보다 미래인 문서는 기본
빌드에서 제외합니다. 페이지·카탈로그에도 같은 규칙을 적용하며 목록, RSS,
사이트맵에도 넣지 않습니다. `draft`는 YAML 불리언 `true` 또는 `false`여야 합니다.
제외되는 문서도 필수 메타데이터는 검증하지만 본문과 첨부 파일은 렌더링하지 않습니다.

`--include-drafts`와 `--include-future`를 각각 지정하면 미리보기나 빌드에 포함합니다.
미래 날짜인 초안은 두 옵션을 모두 지정해야 합니다. 옵션을 넣은 빌드 결과에는 초안과
미래 글도 실제로 출력되므로 배포하지 않도록 주의하세요. 사이트에 지정되지 않은
현재 시간은 사용자의 PC가 아니라 빌드를 실행하는 환경의 UTC 시계를 기준으로 합니다.

## 지원 문법

Python-Markdown `extra` 확장으로 표, 각주, 정의 목록, 약어, HTML 안의 Markdown,
속성 목록과 표준 추가 문법을 지원합니다. 기본 Markdown의 제목, 인용, 링크, 이미지,
목록, 강조, 인라인 코드와 코드 펜스도 사용할 수 있습니다.

Pymdown Extensions에서는 다음 문법을 활성화합니다.

- 중첩 코드 펜스와 코드 블록 언어 지정
- task list: `- [ ] 할 일`, `- [x] 완료`
- 취소선: `~~취소된 문장~~`
- 아래 첨자: `H~2~O`

Naru 자체 확장은 URL 자동 링크, 백틱으로 감싼 도메인 링크, 외부 링크의 새 창 속성,
YouTube 미리보기, 글 폴더의 로컬 이미지 복사를 처리합니다. YouTube 미리보기는
`[YouTube 미리보기: 영상 제목](https://youtu.be/VIDEO_ID)` 형식으로 작성합니다.
다른 게시물이나 페이지를 가리키는 상대 Markdown 링크는 해당 문서의 생성 URL로
변환하며 쿼리와 앵커를 유지합니다. 빌드 대상에서 찾을 수 없는 링크는 원래대로
두고 원본 파일과 링크를 빌드 로그에 경고합니다. 빌드한 글·페이지 내부의 같은
문서 또는 다른 문서 앵커도 확인하며, 존재하지 않는 앵커는 로그에 경고합니다.
경고는 빌드를 중단하거나 화면에 표시하지 않습니다. 외부 URL, 비 Markdown 파일,
정적 페이지와 아카이브의 앵커는 이 검사 범위가 아닙니다. 로컬 이미지 URL에는
`base_url`을 반영합니다.
제목의 자동 앵커는 한글을 보존합니다. 이전 버전에서 한글 제목의 자동 생성 앵커를
직접 링크했다면 주소가 달라질 수 있으므로 확인하세요.

## 제한과 오류

- `.md` 파일은 반드시 `---`로 시작하고 닫는 `---` 줄이 있어야 합니다.
- front matter의 필수 값, 날짜 형식과 슬러그는 빌드할 때 검증합니다.
- 글 폴더의 로컬 이미지가 존재하지 않거나 허용된 경로를 벗어나면 빌드 오류입니다.
- 사용자 정의 Markdown 확장은 현재 설정으로 등록할 수 없습니다.
- Markdown의 HTML은 정화하지 않으므로 신뢰할 수 있는 콘텐츠만 빌드하세요.

문법 호환성은 완전한 CommonMark/GFM 구현을 의미하지 않습니다. 이 가이드에 없는
확장이 필요하면 먼저 예제와 기대하는 HTML 출력을 테스트로 추가해 지원 범위를 정합니다.
