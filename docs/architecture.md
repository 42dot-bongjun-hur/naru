# Architecture

## 제품 목표

Naru는 간단한 설정으로 Markdown을 정적 사이트로 바꾸는 생성기입니다. 한국어에
친화적이되 한국어 전용 시스템을 뜻하지 않으며, 원문과 사용자 파일을 보존하고
결과가 예측 가능해야 합니다.

현재 제공하는 한글 관련 기능:

- UTF-8과 BOM이 있는 Markdown·YAML, 한글 제목·본문·태그·파일명 처리
- 한글 제목을 보존하는 목차 앵커, 한글 글 슬러그와 카테고리·태그 아카이브
- 한글 파일명이 포함된 로컬 이미지 URL 인코딩 및 파일 복사
- 상대 Markdown 링크 변환과 생성된 콘텐츠의 앵커 확인

한글 친화성을 강화하기 위한 검증 가능한 다음 목표:

1. 한글 글 슬러그와 카테고리 주소의 정규화·중복 처리 및 URL 인코딩이 운영체제와
    반복 빌드에 관계없이 안정적인지 계속 테스트합니다. 기존에 고정된 일부 카테고리
    주소는 호환성을 위해 그대로 유지합니다.
2. 한글·영문 혼합 문서, 공백 및 퍼센트 인코딩이 포함된 파일명·이미지·문서
    링크를 실제 하위 경로 배포 결과로 검증합니다.
3. 주요 설정·콘텐츠·링크 오류에서 파일과 해결 방법을 명확히 제공하고, 한국어
    사용자도 이해하기 쉬운 진단을 제공합니다. 현재 오류 메시지는 주로 영어입니다.
4. 검색 기능을 도입할 때 한글 조사와 띄어쓰기를 포함한 실제 검색 사례를 기준으로
    설계합니다. 검색이나 초성 검색은 아직 제공하지 않습니다.

## 책임 경계

Naru는 사이트 콘텐츠를 소유하지 않는 재사용 가능한 엔진으로 설계합니다.

```text
site project A ─┐
                ├── shared Naru package ──> each site's own output directory
site project B ─┘
```

각 사이트 프로젝트가 소유할 항목:

- 사이트 이름, 원본 URL, 기본 경로, 분류명 등 사이트 설정
- Markdown 글과 정형 데이터
- 콘텐츠와 독립적으로 덮어쓸 템플릿, 스타일, 이미지와 기타 정적 파일
- 빌드 결과물 및 배포 설정

Naru가 소유할 항목:

- 설정 파싱과 검증
- 콘텐츠 로딩 및 front matter 정규화
- URL/출력 경로 계산
- HTML 렌더링과 정적 리소스 복사
- 기본 템플릿과 스타일 제공
- RSS, sitemap, robots.txt 등 선택적 산출물 생성

각 사이트는 Naru 패키지를 설치해 사용하고 자체 출력 디렉터리를 관리합니다.
Naru는 다른 사이트의 출력이나 입력 디렉터리를 빌드 결과로 사용하지 않도록
출력 경로와 소유권을 확인합니다.

## 패키지 경계

- `naru.cli`: 명령행 인자, 출력 경로 검증과 빌드 프로세스 실행
- `naru.config`: 사이트 설정 로딩 및 검증
- `naru.engine.loader`, `metadata`: 콘텐츠 로딩과 front matter 정규화
- `naru.engine.build`, `routes`: 페이지 데이터 구성과 URL·출력 경로 계산
- `naru.engine.templates`: 빌드 범위의 Jinja 환경, 사이트별 재정의와 부분 렌더링
- `naru.engine.seo`: RSS·sitemap의 XML 직렬화, robots.txt와 OG 템플릿 데이터
- `naru.engine.ads`: 광고 렌더링 조건과 부분 템플릿 데이터

`content/posts/`와 `content/pages/`의 Markdown을 읽습니다. 카탈로그는 글의
front matter에 `layout: catalog`를 지정하고, 목록은 같은 폴더의 동명
`.sites.yml`에서 읽습니다. 첫 번째 폴더명이 있으면 이를 기본 카테고리로 사용하며,
명시된 `category`는 폴더명보다 우선합니다. 루트 카탈로그의 기본값은 `bookmark`입니다.
카탈로그는 콘텐츠 페이지, 홈과 통합 목록, 카테고리 허브, RSS 및 사이트맵에 반영됩니다.
같은 출력 경로를 쓰는 콘텐츠는 빌드 전에 거부합니다.
이전 JSON 카탈로그나 front matter의 `sites`는 이전 안내와 함께 오류로 처리합니다.

Markdown은 Python-Markdown과 PyMdown Extensions를 사용합니다. `extra` 기반 문법,
중첩 코드 펜스, task list, 취소선을 지원하며 자체 확장으로 URL, YouTube 임베드와
로컬 이미지 경로를 처리합니다. 사용자 문법 계약은 [Markdown 가이드](markdown.md)에
정리합니다.

CLI는 검증한 사이트 설정과 입출력 경로를 빌드 설정 객체로 엔진에 전달합니다.
엔진은 빌드 범위의 설정을 사용하며 import 시 환경 변수를 요구하지 않습니다.
빌드가 끝나면 설정 범위가 정리되어 이후 빌드에 남지 않습니다.

## 설정과 출력

`naru build`는 사이트 루트와 출력 디렉터리를 받습니다. 사이트 루트의
`naru.yml`에서 설정을 로드하고 검증합니다. 출력 폴더는 비어 있거나 동일한
사이트의 Naru 빌드가 남긴 `.naru-output` 표식이 있어야 합니다.

빌드 시 출력 폴더의 HTML과 일부 정적 파일을 정리하거나 교체합니다. 따라서
사용자가 관리하는 파일은 출력 폴더가 아닌 콘텐츠·정적 파일 디렉터리에 둡니다.
기존 출력의 복사본으로 임시 빌드를 수행하며 성공 후 교체합니다. 교체 실패 시
이전 출력을 복구하고, 복구까지 실패하면 백업 경로를 오류로 알립니다. 출력 폴더
내 심볼릭 링크는 허용하지 않습니다. 첨부 이미지는 생성 기록과 내용 해시를 비교해
기록된 파일만 정리하며, 기록 도입 이전의 파일은 자동 삭제하지 않습니다.
설정은 `site_name`과 `site_origin`만 필수이며 나머지는 검증된 기본값을
사용합니다. `site_origin`은 빌드 시 `--site-origin`으로 지정할 수도 있습니다.
사이트 템플릿이 있으면 파일별로 우선하고, 없는 템플릿은
패키지에 포함된 기본 파일을 사용합니다. 기본 헤더를 사용하는 사이트는
패키지 스타일을 사용하거나 사이트의 `assets/naru.css`로 덮어쓸 수 있습니다.
Jinja2로 템플릿을 렌더링하며 자동 이스케이프와 엄격한 미정의 변수 검사를
사용합니다. 사이트 템플릿을 패키지 기본 템플릿보다 먼저 찾고, 공통 HTML과
Markdown 렌더링 결과만 명시적으로 HTML 조각으로 전달합니다. 기본 카탈로그 항목은
템플릿에서 직접 반복합니다. 글 메타정보·관련 글·작성자·목차·공통 링크·광고·
리다이렉트·OG 이미지도 기본 템플릿이 소유합니다. Python은 표시할 항목과 값을
준비하며 JSON-LD는 Jinja의 `tojson`, RSS·sitemap은 ElementTree로 직렬화합니다.
Jinja 환경도 설정과 함께 빌드가 끝나면 정리되어 다음 사이트에 남지 않습니다.
변수 계약과 호환성은 [템플릿 가이드](templates.md)에
정리합니다.

## 초기 설정 스케치

`examples/basic-site/naru.yml`은 전체 설정 필드의 예시입니다. 예제의 빈
`site_origin`은 배포 시 GitHub Pages 설정으로, 로컬 빌드 시에는
`--site-origin` 옵션으로 지정합니다. 포함된 예제 글은 패키지의 기본 템플릿과
스타일로 빌드할 수 있습니다.

## 호환성 원칙

- 잘못된 설정이나 누락된 파일은 원인을 포함해 실패시킵니다.
- 사이트별 URL 경로와 출력 루트를 빌드마다 명시적으로 지정합니다.
- 생성 파일과 사용자가 관리하는 정적 파일의 소유권을 구분합니다.
- 설정과 콘텐츠의 변경이 다른 사이트의 빌드에 영향을 주지 않도록 합니다.
